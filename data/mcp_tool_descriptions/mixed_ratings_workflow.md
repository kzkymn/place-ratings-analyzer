# 評価の割れる店探しワークフロー

🔧 応用: エリア内の評価の割れる店を探したい場合
このツール単体の地域＋カテゴリ検索では評価の割れる店を網羅的に洗い出せないが、外部の情報源と
組み合わせれば十分可能。以下はレストランに関しての実例（食べログを使用）。同じ考え方
（対象カテゴリのレビュー/ランキングサイトを評価点順に並べて候補を洗い出す）は他の業種にも
応用できるはずだが、未検証である。

手順:
1. 対象カテゴリのレビュー/ランキングサイト（レストランなら食べログ）を評価点順（降順）に
   ソートする。
2. 閾値（例:「3.10点未満」）を下回る店のうち、閾値に近いものから見る（例: 3.09〜3.05）。
   詳しい理由は後述するが、この作業をするうえで下記2点に注意。
   - 3.00まで遡る作業は不要。点数が下がるほど逆に有用な情報が得にくくなるため。
   - 点数が「-」（点数なし）の店と、口コミ数が数件しかない店は低評価候補から除外。
3. 候補の店名・ジャンル表記を確認し、次のいずれかに該当する候補があれば、除外してよいか
   ユーザーに確認する: (a) ユーザーが求める業種と異なる候補（例: 食事目的の店探しにおける
   バー・スナック等の飲み専門店）、(b) 全国/地域チェーン店。
4. 候補が多く全件を確認しきれない場合は、口コミ数が多い候補を優先する。
5. 残った候補を、店名＋地名の単体クエリとしてこのツールに1店ずつ投げ、評価分布を確認する
   （単体クエリは地域＋カテゴリ検索のような偏りを受けない）。

各手順の注意点（背景・理由）:
- 手順1: レビューサイトの既定の並び順は評価点順とは限らない（食べログの既定は
  「予約・PR店舗優先順」）。評価点順（降順）で見るには`?SrtT=rt&Srt=D&sort_mode=1`の
  GETパラメータをURLに付与する。
- 手順2: 点数の下限に近い店は閉店済み・開業間もない店が多く、調べても有用な情報が
  得られにくい。Google側で★1が多い店でも、食べログ上は3.08のように閾値をわずかに
  下回る程度に留まることが多く、そのゾーンを重点的に調査すべき。
- 手順3: 全国/地域チェーン店は、レビューサイトの評価文化上（個性・独自性を重視する食通
  コミュニティ等）独立店より系統的に低く採点される傾向があり、低スコアが実際の接客・品質の
  悪さを意味するとは限らない。除外は必須ではなくユーザー確認が前提だが、確認自体を省略
  しないこと。
- 手順4: 口コミ数が一桁台の候補は偶然の低評価に引きずられているだけのことが多く、実際に
  調べると高評価だった実例が多数ある一方、口コミ数が二桁以上ある候補は、低い評価が偶然
  ではなく一定数のユーザーに共有された印象である可能性が高い（実例: 口コミ数一桁の候補は
  ほぼ高評価だったが、口コミ数十件規模で★1が3割前後を占め、具体的な品質面の指摘コメントが
  付いていた店も見つかった）。
- 手順5: 候補数に比例して合計処理時間が積み上がる（1店あたり約15〜20秒、下記⏱️参照）ため、
  候補が多い場合は事前にユーザーへ時間がかかる旨を伝えること。
- 手順5(該当判定): 「確認が必要な店」への該当は、口コミ数が十分ある候補は★1（＋★2）比率
  __THRESHOLD_PERCENT__%超を単独の基準とする。他候補との比較や`quality_level`ラベル、分布の見た目では判断しない。
  口コミ数が少ない候補は比率が振れやすいため、この基準をそのまま機械的に当てはめず、
  手順4の考え方に従って慎重に扱う。

結果をユーザーへ提示するとき:
該当した店（上記の基準を満たす店）は「確認が必要な店」として紹介する。伝えるのは★1・★2の件数と比率という観測事実と、
それについてのLLM自身の言葉による説明に限る（この文書の記述は候補を絞り込むためのLLM向けの
指針であり、店舗ごとの論評文ではない）。低評価の理由（例: 開店直後のオペレーション不備、
価格重視で味・質を割り切っている等）は、時間の経過で改善済みだったり、店の欠陥ではなく
ユーザーの好み・許容範囲次第だったりすることがあり、口コミの時期や内容次第では現時点でも
同じ状況とは限らない。この留保も伝えたうえで、最終判断は最新の口コミ本文をユーザー自身が
Googleマップ上で確認して行うよう促す。

手順1・2で外部サイトへのアクセスが失敗した場合:
Webページ取得機能で同一ドメインへの短時間の連続アクセスが取得エラーで失敗することがある。
この失敗は先方サイトによる遮断とは限らず、利用しているツール側の制約によることも多いため、
原因を先方のアクセス拒否と早合点しないこと。対応としては、取得の間隔を空けて再試行する、
それでも解決しない場合はユーザーに該当ページを開いてもらい内容を貼ってもらう、の2通りが
ある（通常のWeb検索でも店舗のネガティブな情報は見つかりづらく、有効な代替にならないことが
ある）。
